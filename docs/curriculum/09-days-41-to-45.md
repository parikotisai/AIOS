# Days 41–45 — Finish, Polish, Write-Up

**Where you stand:** the explain feature works, the generate-code feature returns structured output, and one self-correct retry cycle works — none of it capped, logged, or eval'd yet.

---

### Days 41–42 — Finish the self-correct loop, and finish failure handling
- Cap the Day 40 retry loop at a fixed number of attempts (e.g. 3) — an AI that can't fix its own code in 3 tries should fail loudly with a clear message, not loop forever or silently give up.
- Log every attempt (what was tried, what error came back) so you can see the self-correction happening, not just the final result.
- Separately, make sure anything you type directly into the editor (not through the generate box) that your evaluator can't handle yet also fails safely — catch it, show a clear message, no retry loop needed there since there's no AI-generated code to correct.
- **Done when:** you've deliberately triggered a failure that takes 2 retries to fix and watched it succeed on attempt 2, **and** deliberately triggered one that can't be fixed in 3 tries and watched it fail safely with a readable log of what was attempted.

### Days 43–45 — Eval suite, polish, and write-up
- Build a small eval suite: a fixed list of 10–15 algorithm requests ("bubble sort," "reverse a string," "find the max of a list," etc.). Run each one through the full generate → run → self-correct pipeline and record: did it succeed, and on which attempt (1st try, or after N retries)?
- This isn't a new feature — it's your Day 37–42 pipeline, pointed at a fixed test set instead of one request at a time. The score (e.g. "12/15 succeed on first try, 3/15 needed one retry") is a real, honest number about your own system, not a vibe.
- Write a short README: what it does, why you built it, a GIF of it running, and the eval suite's score.
- Write 3–4 sentences you could say out loud in an interview about how the tracer actually works — the schema, the call stack, the self-correct loop, the hardest part you solved.
- **Done when:** a stranger could open this repo and understand what it does in 5 minutes, and your eval suite's results are in the README as a real, current number.
