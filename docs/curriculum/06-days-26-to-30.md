# Days 26–30 — Backend Tests, Proof, and CI

**Where you stand:** Playwright is installed, with a page-load test, a UI-interaction test, and the start of a correctness test.

---

### Day 26 — Finish the correctness test, then make it data-driven
- Complete the test from Day 25: run `x = 5\ny = x + 3` through the UI, assert the final panel shows `y = 8`.
- Then generalize it: instead of one hardcoded snippet, define a list of `(code, expected_result)` pairs — cover normal cases, at least one string/list case, and deliberate edge cases (empty list, division producing a non-integer, a condition that's false on every branch). Loop the same test logic over all of them instead of copy-pasting one test per case.
- **Done when:** this test would genuinely catch a wrong-arithmetic bug in your evaluator, **and** adding a new case to your data list is a one-line change, not a new test function.

### Day 27 — Backend-only test
- Hit `/trace` directly (no browser) with code, assert the JSON response is correct. Much faster than a UI test.
- **Done when:** you have at least 5 of these, covering assign, if/else, while, and function calls.

### Day 28 — Prove the tests work
- Deliberately break your evaluator — comment out or change one line of real logic.
- Run your full test suite.
- **Done when:** a broken tracer produces a red (failing) test, not a silent pass. If nothing fails, your tests aren't actually testing anything yet — go fix that before moving on.

### Days 29–30 — CI, across browsers
- Wire your tests into GitHub Actions so they run automatically on every push.
- Configure Playwright to run your UI tests against at least Chromium and Firefox (`playwright.config` projects), not just whichever browser you've been developing against.
- **Done when:** you see a green checkmark on a real commit in GitHub, **and** the CI run shows your tests passing on more than one browser.

---

**Phase 2 checkpoint — done.** Your own tool is now guarded by your own tests, running automatically.
