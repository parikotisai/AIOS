# Days 36–40 — Explain Button, Code Generation, Start Failure Handling

**Where you stand:** you've made your first LLM API call and started wiring an "Explain this step" button.

---

### Day 36 — Finish the explain button
- Make it work reliably across different step types (assign, call, return, loop, condition) — not just the one you tested first.
- **Done when:** every step in a full recursive-function trace has a correct, readable explanation available.

### Days 37–39 — Generate example code, as structured output
- Add a box where typing something like "bubble sort" asks the AI for Python code, and drops the result straight into your editor.
- Don't ask the AI for raw code text — ask for a JSON object matching a schema you define (Pydantic): `{"code": str, "algorithm_name": str, "uses_features": list[str]}` or similar. `uses_features` matters directly for Day 40: it tells you up front whether the generated code needs something your evaluator doesn't support yet, before you even try to run it.
- Validate the response against your schema; if it doesn't parse, that's a failure case too — handle it the same way Day 40 handles execution failures.
- **Done when:** this works for at least 3 different requested algorithms, each returns a valid structured object (not just code text), and each one runs cleanly through your evaluator without crashing it.

### Day 40 — Start the self-correct loop
- When generated code fails in your evaluator (a language feature you haven't built, or a runtime error), don't just catch and display the error — capture the exact error message and feed it back to the AI in a second API call: "this code failed with `<error>`, fix it and return the corrected version" (same structured schema as Day 37–39).
- Get one full retry cycle working first: generate → run → fail → feed error back → regenerate → run again. Capping attempts and logging each try is tomorrow's problem (Day 41–42) — today is just proving one retry works.
- **Done when:** you can deliberately trigger one known failure (e.g. ask for code using a feature your evaluator doesn't support) and watch it self-correct on the second attempt, not just error out.
