# Days 16–20 — Recursion, Backend Wiring, Real Frontend

**Where you stand:** your call stack works for a simple, one-call function.

---

### Day 16 — Finish function calls (recursion checkpoint)
- Test your call stack against a small recursive function — factorial or fibonacci of a small number (3 or 4).
- This is the single hardest checkpoint in the whole project: your frame stack has to correctly keep separate copies of the same variable name (e.g. `n`) for each active call.
- **Done when:** a recursive function produces a full, correct trace — every call and return, in order, with the right local variables at each level.

### Days 17–18 — Real backend wiring
- `/trace` now takes real code as text (not hardcoded), runs it through your evaluator, and returns the full JSON trace.
- Handle bad code (syntax errors) without crashing the server — return a clear error instead.
- **Done when:** you can POST any small Python snippet covering everything so far and reliably get back a correct trace.

### Days 19–20 — React frontend, for real, and a live deployment
- Build: a code input box, a Run button, step controls (prev/next/play), a variables panel, and current-line highlighting.
- Wire it to your own backend — no more fake data anywhere.
- Deploy both sides somewhere live — e.g. the backend to Railway or Render, the frontend to Vercel or Netlify. This is the "not just localhost" scope item: a URL you can hand to someone else, not just something running on your machine.
- **Done when:** you type code, hit Run, and watch it step through correctly, live, on your own machine — **and** the same thing works at a public URL, not just `localhost`.

---

**Phase 1 checkpoint — done.** You have a working, from-scratch tracer and UI covering assignment, arithmetic, if/else, while, and function calls (including recursion), deployed live, built entirely by you.
